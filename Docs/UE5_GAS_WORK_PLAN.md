## 2. 本轮范围与完成标准

本轮实现：

1. 保留当前场景、模型和动画资源，稳定运行现有基础玩法。
2. GAS 统一管理 Health / MaxHealth 和伤害。
3. 玩家与敌人死亡只触发一次，死亡后停止移动及攻击。
4. 支持一把基础武器的射击、弹药、换弹和中断。
5. 敌人可以发现、追踪、攻击玩家，死亡后停止 AI。
6. HUD 显示血量和弹药，游戏支持胜利、失败及重开。
7. 能打包运行，并整理实际实现的项目说明和演示材料。

暂不排入本轮：联网预测、多武器背包、复杂装备、复活系统、EQS、对象池、完整 Lyra 架构迁移。现阶段重开关卡即可，不要求在同一 Pawn 上原地复活。

**第一个里程碑 M1：现有射击 → GAS 扣血 → 敌人死亡一次 → AI 停止。**

## 3. 开发原则

- 主要使用 UE C++；资源配置和表现使用 Blueprint / Animation Blueprint。此项目不为使用 Lua 而额外引入 Lua 插件。
- 一次只迁移一条功能链，迁移前记录原行为，迁移后立即验证。
- 血量的唯一来源是 AttributeSet，不保留另一个独立扣血的蓝图 Health。
- 先沿用现有射击入口施加 GameplayEffect；伤害接通并不要求先把射击做成 GameplayAbility。
- C++ 创建必要组件、定义规则和事件；模型、动画类、蒙太奇及音效由蓝图配置。
- 普通跑跳继续由 CharacterMovement 驱动，AnimBP 根据速度和空中状态切换表现；本轮不强制将跑跳做成 GA。
- 构建新公共基类前先检查 AMyShooter 与现有蓝图的关系，避免盲目重命名或建立两套相同基类。
- 本轮按单机、关卡重开设计，ASC 放在角色上；未来做联网或跨 Pawn 保留状态时，再评估 PlayerState ASC。
- 不用每帧轮询代替血量、弹药、死亡等事件通知。
- 表格中的类名和资源名是建议名，实际实施前结合已有命名确认。

## 4. 目标职责划分

| 对象 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| 公共战斗 Character | 持有 ASC / AttributeSet、初始化、死亡状态与事件 | 直接操作 HUD 控件 |
| 玩家 Character | 输入桥接、视角、玩家操作 | 再存一份独立血量 |
| 敌人 Character | 敌人配置、受击与死亡表现接口 | 将所有寻路和决策塞入 Tick |
| AttributeSet | Health / MaxHealth、数值约束 | 播放动画、停止行为树、判断胜负 |
| GameplayEffect | 初始属性和伤害等数值效果 | 管理完整射击循环 |
| GameplayAbility | 射击 / 换弹 / 攻击的执行与中断 | 永久保存一套重复的武器数据 |
| 武器 Actor 或组件 | 伤害、射速、弹匣、当前弹药等配置与状态 | 独立重复驱动一套开火循环 |
| AIController / 行为树 | 目标选择、追踪、攻击条件 | 直接扣目标的独立 Health 变量 |
| GameMode | 当前对局规则、胜负和结束状态 | 直接创建并操纵所有界面细节 |
| PlayerController / HUD | 创建界面、订阅数据、显示结算 | 判断伤害是否有效 |
| AnimBP / 角色 BP | 模型配置、动画、音效、特效 | 再次执行已迁入 C++ 的扣血和死亡规则 |

公共基类有两种可选落地方式：让现有 AMyShooter 承担公共角色职责，或新增公共父类并让 AMyShooter 继承它。**T01 根据蓝图父类检查结果选一种，避免同时实现两种。**

### T02：将已有射击接到 GAS 伤害

建议的最小方案：
- 创建 Instant 的伤害 GameplayEffect。
- 用 SetByCaller 的 Data.Damage 传入正数伤害，在 GE 中以负向修正扣除 Health。
- 首轮可直接修改 Health，不强制增加 Damage 元属性或 ExecutionCalculation；以后有护甲、暴击时再扩展。
- AttributeSet 对 Health 做有效范围约束，至少覆盖效果执行后的结果。
- 明确 EffectContext 的来源角色、武器和命中信息，便于后续击杀归属。
- 命中后通过 ASC / 接口找到可受伤对象，逐步移除对某个敌人 BP 的专用 Cast。
- 原 Take_Damage 可以暂作兼容入口，但只转发伤害，停止独立扣血。

验收例子：
- [ ] 敌人初始 100 HP，每发 25：依次得到 75、50、25、0。
- [ ] 单次 150 伤害后 HP 为 0，不出现负数。
- [ ] 未命中 / 命中无 ASC 的场景物件不会报错。
- [ ] 一发命中只应用一次伤害效果。
- [ ] 射击原有音效、特效与命中行为没有重复执行。

派工：

### T03：死亡只触发一次，并停止角色活动

工作：
- 定义唯一的死亡入口 BeginDeath 和表现结束入口 FinishDeath；名称可按工程规范调整。
- 使用明确死亡状态 / State.Dead 标签，在广播死亡事件之前先标记，避免回调重入。
- Health 归零只触发一次死亡处理；初始化失败不能被误判为正常战斗死亡。
- 取消攻击与换弹能力，阻止以后激活；清除仍由旧蓝图持有的攻击定时器。
- 停止 AI 移动与持续决策：StopMovement；使用行为树时再停止对应 Brain 逻辑。
- 关闭移动和适当的碰撞响应，尸体需要的碰撞单独配置。
- Blueprint 负责死亡蒙太奇、布娃娃、音效等表现。
- 普通角色移动可立即关闭；若死亡蒙太奇依赖 Root Motion，单独确定移动策略。
- 表现结束后清理；没有蒙太奇、动画中断或通知未到达时也要有兜底清理。

### T05：GA_Reload 与取消

工作：
- 明确弹匣容量、备用弹药及换弹时长。
- 本轮采用“换弹完成时一次性补弹”的规则。
- 满弹、无备用弹药、死亡或已在换弹时拒绝重复换弹。
- 开火和换弹不能同时执行，明确互斥标签或等效规则。
- 动画通知或定时器只能有一个实际补弹入口，避免两边都补弹。

## 6. Git 与资源操作约定

- 从当前 develop 和已保存基线开展功能开发；新功能分支建议 codex/gas-foundation 等，具体由派工指定。
- 当前已有未提交文件，先核对归属并保存，不能 reset / checkout 丢弃。
- 一个可验收阶段一个提交；代码、配套蓝图和必要配置一起保存。
- 保留 Content、Config、Source、.uproject 及必要 Build 资源。
- 继续忽略 Binaries、Intermediate、Saved、DerivedDataCache、IDE 缓存和生成工程文件。
- .vsconfig 是可共享的工具链配置，检查内容后决定是否提交，不当成普通缓存直接删除。
- 大资源先判断是否运行必需，再决定 Git LFS；不按体积直接忽略 uasset / umap。
- 蓝图、地图无法按文本可靠合并，同一阶段尽量由一个人集中编辑同一资产。
- 更改反射声明、继承或默认子对象后，优先关闭编辑器完整编译再重开，避免仅凭 Live Coding 判定结构变更成功。
- 当前文档任务不包含提交、推送或修改游戏功能。后续派工明确是否包含提交 / 推送。
